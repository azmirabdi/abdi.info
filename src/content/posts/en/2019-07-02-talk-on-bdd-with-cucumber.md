`Testing at the centre of the approach, with BDD`

On 3 July 2019 I was able to give a talk with a colleague on behaviour-driven development at the Agile Testing conference, held together with the Clean Code Days in Munich. One point of the talk is agile practice, and testing inside agile projects.

Is it enough to keep test user stories in a Kanban board inside one central piece of software, and then call the testing agile? The agile manifesto, with its values and principles, does not spell out a testing method. It does contain hints for how each agile team should arrive at its own agile testing.

As a software architect, though, my attention sits more on the architecture of the test project itself. Questions such as:

- How do I structure my test modules in an agile project?
- Do I build one monolithic test project, or do I cut it, and if so, how?
- Do I rely on reuse, and if so, of what?

I approach this with the Cucumber framework for Java as the example.
